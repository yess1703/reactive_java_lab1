# Музыкальный стриминговый сервис

Две лабораторные на одних и тех же треках. Первая считает статистику циклом и двумя последовательными стримами. Вторая добавляет задержку чтения страны исполнителя, параллельный стрим, свой `ForkJoinPool` и замеры JMH.

## Что делает программа

1. Создаёт исполнителей, альбомы и треки с корректными случайными характеристиками.
2. Считает количество треков, общую и среднюю длительность, сумму прослушиваний и количество треков каждого жанра.
3. Выполняет расчёт циклом `for`, стандартными коллекторами Stream API и собственным коллектором.
4. Проверяет совпадение результатов и измеряет время для **5 000, 50 000 и 250 000 треков**.

## Запуск

Нужны **JDK 17 или новее** и PowerShell. В терминале из папки проекта:

```powershell
.\run.ps1
```

Скрипт компилирует проект, запускает проверки и замеры. JDK берётся из `JAVA_HOME` или папки пользователя `.jdks`. Путь можно указать вручную:

```powershell
.\run.ps1 -JdkPath "C:\path\to\jdk"
```

В IntelliJ IDEA выберите JDK 17+ и запустите `ru.music.Main`. Для отдельного запуска проверок — `ru.music.StatisticsTest`.

Вторая лабораторная запускается отдельно. Скрипт один раз скачивает JMH в `lib`, прогоняет проверки и пишет результаты JMH:

```powershell
.\benchmark.ps1
```

Проверки без замеров: `.\benchmark.ps1 -SkipBenchmark`.

## Где что находится

Основные классы — в `src/main/java/ru/music`.

| Файл | Назначение |
|---|---|
| `Track`, `Album`, `Artist` | Трек, его альбом и исполнитель |
| `Genre`, `AudioFeatures` | Жанр (`enum`) и звуковые характеристики (`record`) |
| `MusicGenerator` | Генерация заданного количества объектов |
| `StatisticsCalculator` | Три способа расчёта |
| `MusicStatisticsCollector` | Собственный коллектор |
| `MusicStatistics` | Результат расчёта |
| `Main` | Запуск, измерение времени и вывод первой лабораторной |
| `ParallelMusicStatisticsCollector` | Параллельный сбор в `LongAdder`, `ConcurrentHashMap` и `ConcurrentSkipListMap` |
| `ForkJoinStatistics` | Свой `ForkJoinPool`: деление списка пополам и последовательный подсчёт фрагмента |
| `src/benchmark/java/ru/music/benchmark` | Замеры JMH и поиск размера, где последовательный и параллельный стримы сравниваются |
| `src/test/java/ru/music/StatisticsTest.java` | Проверки расчётов, генерации и ошибочных данных |

## Результаты

Время измеряется через `System.nanoTime()`: 10 прогревочных запусков и 7 замеров для каждого способа. Генерация данных и вывод текста в замер не входят. Все три способа используют последовательную обработку одной коллекции.

- `results/summary.txt` — статистика и таблицы времени на русском.
- `results/measurements.csv` — все 63 замера с началом, концом и длительностью в наносекундах.

В таблицах **медиана** — четвёртый из семи замеров, отсортированных по времени; **минимум** — самый быстрый замер. Чем меньше время, тем быстрее расчёт. При повторном запуске время может измениться, а файлы результатов перезаписываются.

## Вторая лабораторная

`Artist.country(long delayMillis)` ждёт указанное число миллисекунд и возвращает ту же страну. Ноль означает обычное чтение. Этот метод вызывается, когда статистика группирует треки по странам. Отрицательная задержка отклоняется.

Последовательный вариант — `stream().collect(...)` с `EnumMap` и `TreeMap`. Параллельный — `parallelStream()` с одним общим накопителем: счётчики `LongAdder`, жанры в `ConcurrentHashMap`, страны в `ConcurrentSkipListMap`. Так карты не ломаются, когда несколько потоков обновляют их одновременно. Задержка выполняется до записи в карты, поэтому ожидание идёт параллельно, а не под общей блокировкой.

Свой пул — `ForkJoinPool` на все процессоры машины. Задача делит диапазон треков пополам, пока фрагмент больше порога, и считает фрагмент тем же последовательным накопителем. При задержке порог маленький, чтобы ждать могли сразу несколько потоков. Без задержки фрагменты крупнее: накладные расходы на задачи не съедают сам подсчёт.

JMH измеряет среднее время одного сбора. Для задержки 0 мс размеры начинаются с 1 000, 5 000, 15 000, 50 000, 100 000 и 250 000 треков. Для задержки 1 мс — с 1, 2, 4, 8, 16, 32, 64 и 128. Если на этом диапазоне преимущество не переходит от одного стрима к другому, прогон добавляет соседний размер. Точка равенства — линейная интерполяция между двумя соседними размерами, где более быстрый способ меняется. Если интервалы погрешности JMH пересекаются, отчёт перечисляет эти размеры отдельной строкой.

- `results/lab2-summary.txt` — таблицы и найденное число треков.
- `results/lab2-measurements.csv` — средние JMH и погрешность.
